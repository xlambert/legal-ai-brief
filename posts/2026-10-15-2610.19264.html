What's Really Inside That AI Skill?

A study of 6,309 agent skills finds most listings understate what the code can do

Back when I was running a law library, the scariest thing on a lawyer's computer was a browser toolbar somebody installed because it promised free legal forms. IT spent years locking that down. Add-ins for Outlook and Word went through review. Browser extensions got allow-listed.

Now we have agent skills. If you haven't run into them yet, a skill is a package of instructions (often just a Markdown file), maybe some scripts, and some resources that an AI agent reads and then acts on. Claude has them. Other agent platforms have them. And there are marketplaces where anyone can publish one and anyone can install one.

A new paper on arXiv, Beyond Maliciousness: Static and Runtime Attack-Surface Profiling of Agent Skills from Ratnesh Pandey, Cassie Crossley, and colleagues, looked at what those skills can actually do.

What They Found

The team profiled 6,309 listings from two marketplaces, ClawHub and skillsmp. They analyzed every bundle, checked where the dependencies came from, and ran the skills in a sandbox to watch what happened.

Half the corpus could execute shell commands. 35% could read the filesystem. 31% could write files, and 31% could reach the network. 13% could get at credentials. Seven listings in ten had at least one elevated capability.

Here's the part that got me. Skill authors can list the tools a skill pre-approves in the skill's own header. Only 770 of the 6,061 listings that parsed declared anything at all. Of those that did, 59% understated what the bundle could do. On one marketplace, under-declaring hit 88%.

There's an important nuance in how the authors frame this. Installing a skill grants authority, meaning the standing to direct the agent, and the skill runs with whatever privileges the session already has. So if a lawyer's session can reach the DMS, client email, and the network, so can the skill they just downloaded.

The Law Firm Problem

Lawyers are resourceful. When a tool makes their life easier, they find it and install it. I've seen it with browser extensions, with PDF tools, with every "free" productivity app that ever existed. Skills will follow the same path, and they're easier to install than any of those.

The paper's conclusion is blunt and I agree with it: triage has to start with what the bundle can actually do, and a listing's description of itself is a poor guide.

Pair this with another paper from the same batch, CoRedSkill (arXiv 2610.20049), which shows an attack split across several skills that each look fine on their own. Reviewing one skill at a time won't catch that.

What I'd Do

If your firm is rolling out an agent platform with skills, treat skills like any other code coming into the environment. Set up an intake review. Keep an approved list. Look at the scripts and the dependencies, and check what the skill can touch, especially shell access, file writes, network calls, and credentials. Limit which skills can run in sessions that have access to client data.

I'm a fan of skills. Some of the most useful things I've built with AI lately have been skills, and the firm-specific ones are where a lot of the value lives. We built review processes for Word add-ins for good reasons, and those reasons apply here too.

Who at your firm is going to read the code before a lawyer clicks "install"?
