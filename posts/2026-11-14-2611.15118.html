Seven Neurons and a Date: The Sleeper Agent Problem Comes to Legal AI

Researchers backdoored an AI coding agent by editing fewer than ten neurons, and the SolarWinds case shows why law firms should treat model weights like software

Paper: arXiv:2611.15118 · https://arxiv.org/abs/2611.15118

They first inserted non-malicious test code into SolarWinds' Orion software builds. … In February 2020, seeing that the test code had gone undetected, they began inserting malicious code.

SEC v. SolarWinds Corp. and Timothy G. Brown, S.D.N.Y., Judge Paul A. Engelmayer, July 18, 2024, describing the SEC's amended complaint

What made SolarWinds so damaging is that the malicious code arrived inside a trusted update.

SolarWinds Orion, 2019 to 2020

According to the court's account of the SEC's allegations, the attackers got into SolarWinds' corporate VPN in January 2019 and ran a trial of their attack that November. Over the following months they “inserted malicious code into three different Orion software builds used by approximately 18,000 customers.” SolarWinds disclosed the attack in a Form 8-K on December 14, 2020.

The courts were caught up in it too. In January 2021 the federal judiciary announced new procedures for highly sensitive filings after a federal emergency directive about “a known compromise involving SolarWinds Orion products that are currently being exploited by malicious actors.”

When Judge Engelmayer ruled on the SEC's case in July 2024, he let the securities fraud claims based on the company's Security Statement go forward and dismissed most of the rest. The facts he laid out describe customers who “had unknowingly purchased a corrupted product.”

November 2026

Now apply that to AI. In Lazare, veni foras: Reprogramming Dormant Neurons to Backdoor AI Agents, Yuchen Zeng and colleagues, a group that includes Eric Horvitz, show how to turn an open-weight coding agent into a sleeper agent without any retraining. Their method, which they call Lazarus, edits a handful of “dormant” neurons so that when a trigger string appears anywhere in the agent's context, the agent outputs an attacker's command. Their example trigger is a date, 2027-01-01.

It takes very little. On Nemotron-Terminal-8B, seven neurons out of more than 12,000 fired the payload on at least 98.8% of triggered test runs, with no leakage on the normal runs they checked. Two other open models were just as vulnerable. The paper notes that the core idea was discovered autonomously by Claude Code, which is its own little plot twist.

The edits leave traces. Defenses the authors built flagged 91.4% of edited checkpoints at a 9.7% false positive rate, even without a clean model to compare against. Their conclusion is that model weights should be audited before deployment and monitored for updates, the way we already handle code.

Back at the firm

A backdoored model passes every demo and accuracy test we'd run in procurement, because the backdoor only wakes up on the trigger. That's the SolarWinds pattern with a new kind of software, and the agents we're piloting read client documents and, in some cases, can act on firm systems.

Most firms already ask software vendors where their code comes from and how they'll know if it changes. I'd add the same questions about the model weights inside every legal AI product, especially when a vendor fine-tunes an open model and swaps in updates. And any agent that can run commands should run with the narrowest permissions possible, so a backdoor that does fire has very little within reach.

When did you last ask a legal AI vendor which model is running under the hood, and who can change it?
